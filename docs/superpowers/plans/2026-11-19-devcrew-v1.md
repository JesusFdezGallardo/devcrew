# devcrew v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship devcrew 0.1.0, a Claude Code plugin + marketplace with a security reviewer, a production
investigator (Sentry), two skills (setup-observability, init-project) and a secrets-guard hook.

**Architecture:** One repo that is both marketplace (`.claude-plugin/marketplace.json`, plugin source `./`) and
plugin. Agents and skills are Markdown prompts; the only code is the Node ESM hook (`hooks/`) with pure, unit-
tested helpers in `hooks/lib/`. Sentry is reached through the hosted MCP server declared in `.mcp.json`.

**Tech Stack:** Claude Code plugin format, Node.js ≥ 20 (ESM, no dependencies, `node:test`), Sentry hosted MCP.

**Spec:** `docs/superpowers/specs/2026-11-19-devcrew-v1-design.md` — read it before any task; agent and skill
prompts take their checklists and rules from its "Components" and "Decisions taken after the builder check".

## Global Constraints

- All repo content in **English**; agents answer in the user's language.
- **No personal data** in the repo: no emails, production URLs, IBANs, real account codes, tokens, project names
  of the author's apps. Use placeholders (`<org-slug>`, `my-api`).
- Hook code: Node ESM, **zero dependencies**, works on Windows (PowerShell + Git Bash), macOS, Linux. No `jq`, no bash-only syntax.
- Hook **fails open**: any internal error → exit 0, allow, one warning line on stderr.
- Agents are **read-only**: never Edit/Write, never mutating shell commands, Sentry MCP read tools only.
- Skills **never commit** and **never overwrite** existing files (merge/append, show what was added).
- Plugin name `devcrew`, marketplace name `devcrew`, version `0.1.0`, license MIT.
- Sentry: EU data region, `send-default-pii=false`, SDK is a no-op when the DSN is empty.
- Hook replies: read of a secret → `permissionDecision: "ask"`; `git add` of a secret or `git commit` with a staged
  secret → `"deny"`; otherwise no output, exit 0.
- Commit messages: imperative English, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Files that look secret but aren't (`.env.example`, `.env.sample`, `.env.template`, `id_rsa.pub`, a README that
   mentions `.env`, `echo` of a string containing `.env`) must be allowed silently — Task 2 / Task 3 tests.
2. Windows paths and case (`C:\proj\.ENV`, `config\Credentials.json`, `.\certs\server.PEM`) must be detected —
   Task 2 tests.
3. Chained/compound commands (`npm test && cat .env`, `git add src/ .env`, `type .env | findstr X`) must be caught
   in any segment — Task 3 tests.
4. `git commit -a`/`-am` with a modified **tracked** secret (not staged yet) must be denied — Task 3 test.
5. Hook input that is malformed JSON, a tool it doesn't know, a cwd that isn't a git repo, or git missing from
   PATH → allow with a warning, never a block or a crash — Task 4 tests.

### Task 2: Secret path detection

- Test: `hooks/lib/secret-paths.test.mjs`

**Interfaces:**
- Produces:
  - `isSecretPath(filePath: string): boolean` — basename-based, case-insensitive, accepts `\` and `/`.
  - `globToRegExp(glob: string): RegExp` — `**` any path incl. `/`, `*` any chars except `/`, `?` one char; matched
    against the path relative to project root with `/` separators.
  - `loadAllowlist(projectRoot: string): string[]` — reads `<root>/.devcrew.json` → `secretsGuard.allow`; missing
    file or invalid JSON → `[]`.

    `tokens/StoredCredential`.

### Task 3: Shell command analysis

**Files:**
- Create: `hooks/lib/command-check.mjs`
- Test: `hooks/lib/command-check.test.mjs`

**Interfaces:**
- Consumes: `isSecretPath`, `isAllowed` (Task 2).
- Produces: `checkCommand(command: string, ctx: { projectRoot: string, allow: string[], gitFiles: (args: string[]) => string[] }): { decision: 'allow'|'ask'|'deny', reason?: string }`
  — `gitFiles` returns file names from a git invocation (injected so tests need no repo).

- [ ] **Step 1: Write failing tests.**
  - ask: `cat .env`, `head -n 5 config/.env.local`, `type .env`, `Get-Content .\.env`, `gc credentials.json`,
    `Select-String -Path .env -Pattern X`, `grep KEY .env`, `npm test && cat .env`, `type .env | findstr X`,
    `cp .env /tmp/x`, `Copy-Item .env x.txt`, `less "server.pem"`.
  - deny: `git add .env`, `git add src/ .env`, `git add -- credentials.json`.
  - deny on commit: `git commit -m "x"` with `gitFiles(['diff','--cached','--name-only'])` → `['src/a.ts','.env']`.
  - deny on `git commit -am "x"` when cached is `[]` but `gitFiles(['diff','--name-only'])` → `['credentials.json']`.
  - allow: `git commit -m "x"` with cached `['src/a.ts']`; `echo "copy .env.example to .env"`; `cat .env.example`;
    `ls -la`; `git status`; `cat README.md`; `cat .env.production` with `allow: ['.env.production']`.
  - every non-allow result has a `reason` naming the file and, for `ask`, mentioning `.devcrew.json`.
- [ ] **Step 2:** Run tests → FAIL.
- [ ] **Step 3:** Implement. Split into segments on `&&`, `||`, `;`, `|`, newlines; tokenize each segment on
  whitespace honoring single/double quotes. Read commands (first token, case-insensitive): `cat`, `type`, `head`,
  `tail`, `less`, `more`, `grep`, `rg`, `findstr`, `get-content`, `gc`, `select-string`, `sls`, `cp`, `copy`,
  `copy-item`, `base64`, `xxd`, `strings`. `git add` → deny if any argument is a secret path. `git commit` → staged
  (`diff --cached --name-only`) plus, when `-a`/`--all` or a combined short flag containing `a`, unstaged tracked
  (`diff --name-only`); deny if any is secret and not allowed.
- [ ] **Step 4:** Run tests → PASS.
- [ ] **Step 5: Commit** `Add shell command analysis for the secrets guard`.

### Task 4: Hook entry point and registration

**Files:**
- Create: `hooks/guard-secrets.mjs`, `hooks/hooks.json`
- Test: `hooks/guard-secrets.test.mjs`

**Interfaces:**
- Consumes: Tasks 2–3.
- Produces: the registered PreToolUse hook. Input (stdin JSON): `tool_name`, `tool_input`, `cwd`. Output on
  ask/deny (stdout, exit 0):
  `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"ask|deny","permissionDecisionReason":"<reason>"}}`.
  Allow → no stdout, exit 0.

- [ ] **Step 1: Write failing tests** that spawn `node hooks/guard-secrets.mjs` with stdin:
  - `Read` `{file_path: "<tmp>/.env"}` → stdout decision `ask`.
  - `Edit`/`Write` on `<tmp>/server.pem` → `ask`; `Grep` with `path: "<tmp>/.env"` → `ask`; `Grep` with
    `path: "<tmp>"` → allow (folder-wide Grep out of scope, spec).
  - `Bash` `{command: "git add .env"}` → `deny`; `PowerShell` `{command: "Get-Content .env"}` → `ask`.
  - `Read` on `.env.production` with `<tmp>/.devcrew.json` allowing it → allow (empty stdout).
  - malformed stdin, unknown tool `Foo`, `Bash git commit -m x` in a non-git temp dir → empty stdout, exit 0,
    stderr starts with `[devcrew]` for the error cases.
- [ ] **Step 2:** Run `npm test` → FAIL.
- [ ] **Step 3:** Implement `guard-secrets.mjs`: project root = `git rev-parse --show-toplevel` from `cwd`, else
  `cwd`; `gitFiles` runs `git <args>` with `execFileSync` in that root (errors → `[]`); everything wrapped in
  try/catch → fail open. `hooks.json`: `PreToolUse`, matcher `Read|Edit|Write|Grep|Bash|PowerShell`, command
  `node "${CLAUDE_PLUGIN_ROOT}/hooks/guard-secrets.mjs"`.
- [ ] **Step 4:** Run `npm test` → PASS; `claude plugin validate .` → no errors.
- [ ] **Step 5: Smoke test in Claude Code.** `/plugin marketplace add <local devcrew path>`,
  `/plugin install devcrew@devcrew`, restart, then in a scratch folder with a dummy `.env`: ask Claude to read it →
